# Agent 评测指标与标注覆盖

这里的“标注完成”指首轮静态标签已准备，并不等于模型运行、自动评分或专家复核已完成。PDF 原文引文均以文件哈希和 PDF 页码固定；人工审核状态目前仍是 **pending**。

| --- | --- | --- | --- |
| 证据检索覆盖（observed gold recall） | 17 道可回答题、逐页原文锚点 | Agent 可；Workflow 无逐步观察，返回 `null` | 在隔离项目分别运行同题；不要把未标记块当不相关块计算 precision@k |

| 循环收敛与错误恢复 | 步数耗尽、空搜索改写、重复搜索场景 | 步数耗尽和重复/空搜索可统计 | 多次运行比较频率；不能用单个静态 gold 代替恢复能力 |

## 禁止误用

- 56 条引文是 **positive anchors**，没有穷尽标注 510 个块对 17 道题的全部相关性。因此不能直接算 `precision@k`、`nDCG` 或“检索到非 gold 块即错误”。
- 3 道弃答题的判断由 AI 辅助全文检查形成；“未找到”不是对世界事实不存在的证明，需独立人工复核，尤其是 PDF 表格和附录。
- 跨论文 `complementary` 是本任务角度的首轮关系标签，不说明两项研究可在同一实验条件下直接比较优劣。
- `answer_rubrics.json`、`claim_challenges.json` 和 `agent_behavior_scenarios.json` 目前是**待接评分器**的标准，不能报告为已经通过的模型测试结果。
- 工作流和 Agent 对比必须固定 PDF 字节、问题、模型版本及预算；记忆实验另行隔离。`samples/*.pdf` 被 Git 忽略，克隆仓库本身不包含论文。

## 建议的后续执行顺序

1. 邀请第二标注人复核关键引文、答案要点、数字单位、弃答题与跨论文关系，记录分歧和裁决。
2. 扩展离线评分器，使其读取答案标准、最终回答、综合结果与 Agent 场景断言；保留机器无法裁定时的人工评审状态。
3. 在隔离项目跑 Workflow/Agent 配对实验，逐案例保存运行 ID、模型与提示词版本、预算、语料哈希和记忆条件。
4. 对正确率、召回、弃答、成本和延迟报告均值及分布；对失败轨迹做原因归类，而不只报总分。
